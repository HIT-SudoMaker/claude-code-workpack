# CCW 整体状态机规格

本规格记录已确认的产品要求及整体状态机方案，供后续实现与验收使用。运行代码尚未完成这次整体迁移。

## Problem Statement

用户的更新选择曾在取消、重新勾选后退回普通安装。安装、清理和续办过程中，命令返回结果与实际文件状态也可能不一致。用户无法确定当前选择是否被记住、程序是否真正完成，以及再次继续会不会重复操作。

当前进度分散在界面暂存、核心生命周期、剩余操作闭包、顺序执行游标及工具内部检查点中。多个地方分别解释进度，增加了修改和定位问题的成本。现有恢复依赖内存，执行后的诊断摘要无法承担进程重启恢复。

用户要求架构极端清爽：职责明确、事实集中、修改局部化，并通过一个整体状态机统一控制操作。

## Solution

以一个整体状态机和一份当前任务记录，统一管理选择、预览、确认、执行、中断和恢复。界面展示状态并提交用户动作；工具模块提供实际操作及验收能力；整体状态机拥有全部流程控制权。

同一用户同时只允许一个 CCW 实例，只保留一份未结束任务。重新启动时先核对实际结果，再展示剩余计划，由用户确认后继续。部分失败保留成功结果；独立工作可以继续，依赖失败项的工作暂停。无法确认结果的项暂停，提供重新检查或重新预览。

未保存的 API 密钥仅存在内存，进程中断后按需重新输入。已经写入的有效配置继续使用。

## User Stories

1. 作为 CCW 用户，我希望检查结果区分已安装、缺失和未知，以便正确选择下一步。
2. 作为 CCW 用户，我希望进入更新后取消勾选再重新勾选仍保持更新意图，以便操作符合我的选择。
3. 作为 CCW 用户，我希望预览显示实际目标、动作和影响，以便执行前判断是否合适。
4. 作为 CCW 用户，我希望修改选择后重新生成预览，以便确认的是最新选择。
5. 作为 CCW 用户，我希望执行沿用已批准的版本、来源和目标，以便继续任务时不会悄悄改变目标。
6. 作为 CCW 用户，我希望重复启动时得到已有实例的提示并退出，以便始终只有一个实例控制操作。
7. 作为 CCW 用户，我希望一次只处理一份未结束任务，以便清楚当前正在做什么。
8. 作为 CCW 用户，我希望关闭或崩溃后重新打开能发现未完成任务，以便恢复工作。
9. 作为 CCW 用户，我希望恢复时先看到已完成、待核对和未执行的工作，以便决定是否继续。
10. 作为 CCW 用户，我希望恢复必须经过我的确认，以便掌握继续修改系统的时机。
11. 作为 CCW 用户，我希望已确认完成的操作只复核结果，以便避免重复安装和重复写入。
12. 作为 CCW 用户，我希望命令回执丢失时先核对实际结果，以便正确处理已经生效的操作。
13. 作为 CCW 用户，我希望无法确认的操作暂停并说明原因，以便选择重新检查或重新预览。
14. 作为 CCW 用户，我希望一个任务失败后保留其他成功结果，以便继续使用已经可用的工具。
15. 作为 CCW 用户，我希望独立任务在某项失败后仍可继续，以便获得可完成的成果。
16. 作为 CCW 用户，我希望依赖失败项的任务暂停，以便避免建立在错误结果上继续操作。
17. 作为 CCW 用户，我希望程序安装成功而配置步骤失败时，仅续办未完成配置，以便避免重新安装程序。
18. 作为 CCW 用户，我希望可以放弃未结束任务并保留成功结果，以便开始新的工作。
19. 作为 CCW 用户，我希望用户已有设置和数据按既有保留规则处理，以便升级架构后原有内容仍然可用。
20. 作为 CCW 用户，我希望卸载程序、解除接入和删除数据仍是明确区分的动作，以便理解各自影响。
21. 作为 CCW 用户，我希望恢复记录不保存尚未写入配置的密钥，以便记录只承担任务恢复职责。
22. 作为 CCW 用户，我希望界面显示和实际执行使用同一份任务事实，以便不会出现显示成功而执行判断失败的矛盾。
23. 作为维护者，我希望新增普通工具时主要修改工具模块及登记，以便核心控制逻辑保持稳定。
24. 作为维护者，我希望新结构替换后删除旧控制逻辑，以便减少需要同时理解的实现。

## Implementation Decisions

### 一个整体状态机

整体阶段收敛为空闲、准备、待确认、执行、暂停、完成。准备包含正常计划生成与恢复核查；两者共用整体状态机。阶段名称作为工作术语，验收以可观察行为为准。

| 阶段 | 职责和迁移条件 |
| --- | --- |
| 空闲 | 提交选择或发现未完成任务后进入准备。 |
| 准备 | 核对实际状态，生成初始或剩余计划后进入待确认；仍有未完成项且无可供确认的独立工作时进入暂停。 |
| 待确认 | 用户确认后进入执行；修改选择后重新准备；明确放弃则回到空闲。 |
| 执行 | 全部目标验收通过后进入完成；无可继续的独立工作且仍有未完成项时进入暂停。 |
| 暂停 | 重新检查或重新预览后进入准备；明确放弃则保留成功结果并回到空闲。 |
| 完成 | 展示验收结果，结束本次任务后回到空闲。 |

有单项失败时，状态机先继续符合条件的独立项。存在未完成项且无可执行工作时，整体才进入暂停。恢复核查期间可以标记符合条件的成功项，但实际变更必须等用户确认。

### 一份记录拥有全部进度

记录保存任务身份和格式版本、已批准意图、固定目标、必要依赖、逐项执行事实及核对依据。每个可独立核实的操作有稳定身份；至少区分尚未派发、已派发、结果已确认、已知失败和待核对。

整体阶段控制何时可以执行；逐项事实描述哪些工作已经发生。依赖暂停、剩余计划、进度显示和结果摘要由同一记录推导。记录只保存影响恢复判断的信息，不复制界面状态或另存一张任意工作流图。

安装程序、配置 PATH 和建立接入可以分别验收，因此分别记录必要事实。记录粒度由能否独立验收决定，普通辅助函数无需变成持久化步骤。

### 统一修改状态

所有用户动作、命令回执和验收结果都交给整体状态机处理。界面和工具模块不能自行推进整体阶段，也不能各自持有可续办的进度副本。

工具模块保留渠道选择、固定版本、操作内容、文件归属和验收判断等专业知识，并返回动作与事实。npm 失败后是否允许 CMD 备用安装仍由 Claude 工具模块判断；整体状态机统一登记、派发、核查和暂停。中央控制逻辑无需认识每个安装器的命令细节。

### 执行和恢复使用同一套规则

目标变更前，先可靠记录派发意图；命令返回或实际结果核对后，可靠更新记录。记录无法可靠保存时暂停新的变更。记录写入需能识别中断及无效内容，普通执行日志不承担这个职责。

重启后将已派发但结果未确认的操作转入核对。已完成项验证仍满足原目标，未执行项保留原目标。核对不能证明完成时暂停，不能仅凭进度文字、退出码或版本相同判断所有动作都已完成。同版本重装有证据时据此判断，无法区分是否执行过本次动作时保留待核对，不推定完成或自动重发。

恢复不重新选择最新版或扩大修改范围。目标、来源或必要证据不能再确认时，要求重新预览。未完成任务可明确放弃；放弃不会自动回滚已经成功的安装与设置。

### 保留少量职责

启动入口负责单实例的获取、释放和异常退出后的识别。操作模块负责唯一状态、任务记录、计划、依赖、执行资格和恢复。工具模块负责实际操作及验收。可靠存储和系统调用是这些模块使用的实现能力。

保留现有对外检查、计划和执行入口以及读写能力限制。菜单和配置保持既有用途，核心规则覆盖所有调用入口。用户不会接触内部步骤格式或记录存储方式。

### 以替换完成迁移

由唯一任务记录替换核心生命周期与独立剩余工作集合、执行闭包中的游标和完成列表、工具私有推进状态、界面保存的续办进度，以及通过进度消息推断依赖资格的逻辑。

现有来源检查、指纹核对、受限系统操作和真实行为回归测试继续复用。已有修复中有价值的判断提取为工具能力；迁移完成的路径删除旧状态管理和过渡包装。不得在旧控制逻辑外长期再包一层总状态机。

## Testing Decisions

以已有的检查、计划、执行接口作为主要且统一的测试入口：提交选择，观察预览，执行，核对真实临时文件系统和命令调用次数。通过重新启动实际进程或重新建立操作实例并读取同一任务记录，证明恢复不依赖旧闭包。终端只增加必要的启动、确认与展示集成验收；不为每个工具新增测试专用入口。

重点验收以下场景：

1. 更新选择在取消、重选、预览和恢复后保持原意图；来源和版本保持冻结。
2. 第二个 CCW 实例拒绝启动；旧实例正常或异常退出后可以正确接管。
3. 派发前中断、产生效果后中断、收到回执但保存结果前中断，都能按记录与实际结果核对。
4. 已确认成功的安装不重复执行；PATH 或接入失败只继续未完成操作。
5. 无法核对的项暂停；依赖项暂停；独立项继续；整批不会误报全部成功。
6. 恢复需用户确认；放弃保留成功结果；存在未结束任务时拒绝直接开始另一份任务。
7. 任务记录保存失败或内容无效时，不派发依赖该记录的新变更。
8. 尚未保存的密钥不进入恢复记录；需要时要求重新输入；已有有效配置继续使用。
9. 临时文件归属、现有用户设置、原程序副本和用户数据保留规则维持有效。
10. 界面与直接调用入口得到相同的选择、冲突、执行和恢复约束。

已有 OfficeCLI、Claude 安装、作用域漂移、设置保留、生命周期和真实终端测试提供故障注入先例。测试以可观察结果为准；状态迁移规则和记录格式校验另以操作模块的明确接口验证。

架构验收还包括删除检查：迁移后的路径只能找到一个进度归属，展示不参与业务判断，新增普通工具不要求在中央状态机枚举其安装阶段。

## Out of Scope

- 多 CCW 实例并发执行、多窗口协作和多份未结束任务管理。
- 通用工作流平台、事件流回放系统、分布式调度和任意流程编程语言。
- 自动整批回滚及外部命令恰好执行一次的保证。
- 在本次架构迁移中新增密钥保管系统或重做整个终端界面。

## Further Notes

已确认的用户取舍是单实例、单份未结束任务、恢复前确认、保留成功结果、按依赖隔离失败、未知结果暂停、尚未保存的密钥恢复时重新输入，以及极端清爽的架构。

跨平台范围沿用项目现有 Windows、Linux、macOS 分支。验收报告分别说明实机、隔离目录和合同测试覆盖，不把某平台的测试结果等同于其他平台的实机验证。

本规格要求以整体状态机替换现有分散控制方式。当前已有的合同测试与安装修复不意味着单实例、持久化恢复和统一控制已全部实现。
