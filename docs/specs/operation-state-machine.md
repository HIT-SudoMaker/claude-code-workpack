# 产品与执行合同

本文说明 CCW 的操作流程、模块职责和执行边界。接入来源与命令见[接入说明](../integrations.md)，编码约定见 [CSU 规范](../standards/typescript-csu.md)。

## 用户操作

首页提供安装配置、检查状态、移除程序、清理数据和退出程序。除只读检查外，操作都要先选择对象、查看预览并确认。模型连接、语言和输出风格已有有效设置时直接复用；需要编辑或缺少必要信息时，先完成表单，再准备计划。

检查页显示名称、状态和路径，仅 Claude Code 显示版本号。插件共用的设置路径只显示一次；技能成员已经列出时，不重复显示套件汇总。读取失败或暂时不能操作的项目仍要显示原因。

变更预览按类别列出动作和影响，合并重复的配置路径及插件生效提示。替换 Skills、删除数据和保留内容的范围必须清楚。默认页面使用简短说明，`--details` 补充诊断码和执行步骤。

## 模块职责

| 模块                        | 管理内容                                       |
| --------------------------- | ---------------------------------------------- |
| `claude.ts`                 | Claude Code 程序、默认设置、模型连接和数据清理 |
| `plugins.ts`                | 清单内插件的安装、更新、启用和停用             |
| `skills.ts`                 | 受管 Skills 来源的发现、替换和安装             |
| `officecli.ts`、`ccline.ts` | 各自的程序、配套内容和接入                     |

多个模块会写入 `settings.json`，但职责各自明确：Claude 管理模型和偏好，Plugins 管理 `enabledPlugins`，CCometixLine 管理 `statusLine`。公共代码负责文件操作和核验，不替各模块决定业务策略。

Context7、GitHub 和 Serena 统一由 Plugins 管理，CCW 不提供令牌表单，也不维护独立 MCP 注册。插件安装成功不等于 MCP 服务已连接。

## 检查、计划与执行

核心接口为 `inspect(signal?, scope?)`、`plan(request, signal?, progress?)` 和 `apply(planId, signal?, progress?)`。检查默认为 `contents`；`data` 只清点可清理数据。请求为 `{ task, selected }`，任务支持 `install`、`uninstall` 和 `clean`，清理任务只接受数据类别。请求不能携带逐项 `action` 或 `removeData`。

检查和计划准备不写入受管目标；准备阶段可以查询来源和暂存资源。计划包含对用户可见的动作、影响和问题，凭据与执行函数留在内部。修改预览或进度对象不会改变执行内容。

CCW 只保留最新一份内存计划，新计划会使旧计划失效，执行开始后计划即被消费。中断或重启后，需要重新检查和确认。命令行对同一用户只允许一个实例运行。

执行前核对目标和来源，执行后核对实际效果。命令退出码不足以证明完成；回执丢失时仍要检查结果，目标发生变化时停止当前步骤，不自动重发或换源重装。

插件安装、更新和登录使用计划绑定的 Claude 入口。已有入口固定路径和内容摘要；同批新安装的 Claude 须先通过核验。程序未就绪时跳过依赖它的操作，插件停用无需运行 Claude，其他独立项目可以继续执行。

取消会停止后续写入，不回滚已经发生的效果；已派发的操作仍需核验。外部探测共用五秒检查预算，执行后的单项核验各有三十秒预算。

| 状态        | 含义                                 |
| ----------- | ------------------------------------ |
| `done`      | 已核验完成                           |
| `partial`   | 已确认部分完成或保留效果，其余未完成 |
| `failed`    | 执行或核验失败                       |
| `skipped`   | 前置依赖未满足                       |
| `cancelled` | 因取消停止执行                       |

每项结束时发送 `checked`，整批复核后发送 `finished`。复核可以修正目标发生变化后的结果；展示层使用核心给出的状态，不自行推断。技能内容已完成但来源记录未确认时单独提示，不将提示计为失败。

## 数据与凭据

移除程序只处理受管程序及所选接入。解除模型连接会移除相关连接字段和凭据助手；停用插件保留文件和市场记录。

替换或移除 Skill 前核对来源和内容摘要，保留手写、其他来源及本地修改。部分移除失败时记录已经完成的操作，允许重新生成计划后重试。

数据清理按缓存与日志、会话与历史、项目记忆、备份和运行数据分类，只处理所选类别的白名单内容。清理前须确认 Claude 已停止；预览列出文件数、目录数、大小和路径。执行时核对文件摘要与目录，删除后再次核验；共享链接目标、其他类别内容和 Claude 配置根目录均予保留。权限不足等失败应保留具体原因。

模型连接与有效凭据分别判断，表单和计划采用相同的校验语义。凭据、原始异常和堆栈不进入页面或公开结果；详细模式也不能显示凭据。

## 验证范围

行为测试覆盖计划消费、互斥、取消、目标变化、凭据隐藏、失败隔离和用户内容保护。Windows 终端通过 ConPTY 验证交互；独立运行包另行验证依赖、资源、许可文件和程序部署。macOS、Linux 的平台模拟不能代替原生环境验收。
